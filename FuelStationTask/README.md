# Симуляция АЗС

Дискретно-событийная симуляция работы автозаправочной станции.

## Сборка и запуск

```bash
javac -d out src/*.java
java -cp out Main [сценарий|параметры]
```

## Компоненты

### Config
Хранит все параметры симуляции: длительность, количество колонок, скорость заправки, пороги, настройки топлива, seed.

### Car
Автомобиль с параметрами:
- `tankCapacity` — объём бака (случайно из {40, 50, 60, 70, 80} л)
- `fuelLevel` — текущий уровень (10-90% от бака)
- `desiredFuel` — желаемый объём заправки (5 до свободного места)
- `arrivalTime`, `startServiceTime`, `endServiceTime` — временные метки

Инвариант: `desiredFuel ≤ tankCapacity - fuelLevel`

### FuelPump
Топливная колонка:
- `flowRate` — скорость заправки (л/мин)
- `busy` — флаг занятости
- `currentCar` — обслуживаемый автомобиль
- Методы: `serve(car)` → время окончания, `release()` → освобождение

### GasStation
АЗС управляет:
- `pumps` — список колонок
- `queue` — FIFO-очередь автомобилей
- `fuelReserve` — текущий запас топлива
- Логика расширения (добавление колонок при длительном ожидании)

### CarGenerator
Генерация потока автомобилей по неоднородному пуассоновскому процессу:
```
Δt = -ln(U) / λ(t), где U ~ Uniform(0,1)
```

Интенсивность λ по времени суток:
| Период | Часы | λ (авто/мин) |
|--------|------|--------------|
| Ночь | 00-06 | 0.03 |
| Утренний пик | 06-10 | 0.25 |
| День | 10-16 | 0.12 |
| Вечерний пик | 16-20 | 0.30 |
| Вечер | 20-24 | 0.08 |

### Event / EventType
Событие симуляции:
- `CAR_ARRIVAL` — прибытие автомобиля
- `SERVICE_END` — завершение заправки
- `FUEL_DELIVERY` — прибытие бензовоза
- `PUMP_OPEN` — открытие новой колонки

### Simulation
Главный цикл обработки событий:
```
while (есть события && время < конец):
    событие = очередь.poll()
    обработать(событие)
```

### Statistics
Сбор метрик: прибыло, обслужено, отказы, время ожидания, загрузка колонок, остатки топлива.

### ConfigPresets
Готовые сценарии: `standard`, `highload`, `shortage`, `stress`, `efficient`, `small`, `peak`, `night`.

## Взаимодействие компонентов

```
Main
 └─→ ConfigPresets → Config
 └─→ Simulation
      ├─→ GasStation
      │    ├─→ FuelPump[]
      │    └─→ Queue<Car>
      ├─→ CarGenerator → Car
      ├─→ PriorityQueue<Event>
      └─→ Statistics
```

## Поток событий

```
CAR_ARRIVAL:
  Car = CarGenerator.generate()
  if fuelReserve < desiredFuel → отказ
  if свободная колонка → serve() → планировать SERVICE_END
  else → в очередь
  планировать следующий CAR_ARRIVAL

SERVICE_END:
  fuelReserve -= desiredFuel
  колонка.release()
  if очередь не пуста:
    car = очередь.poll()
    if waitTime > порог → планировать PUMP_OPEN
    serve() → планировать SERVICE_END

FUEL_DELIVERY:
  fuelReserve = min(fuelReserve + deliveryVolume, maxCapacity)
  планировать следующую FUEL_DELIVERY

PUMP_OPEN:
  добавить колонку
  if очередь не пуста → сразу обслужить
```

## Механизм расширения

1. При `SERVICE_END` проверяется время ожидания автомобиля из очереди
2. Если `waitTime > queueThreshold` (12 мин) → планируется `PUMP_OPEN` через `expansionDelay` (2 дня)
3. Флаг `expansionScheduled` предотвращает множественные срабатывания
4. Максимум колонок ограничен `maxPumps` (10)

## Использование

```bash
java -cp out Main                # стандартный режим
java -cp out Main --list         # список сценариев
java -cp out Main shortage       # сценарий дефицита топлива
java -cp out Main 14 3 100       # 14 дней, 3 колонки, seed=100
```

## Выходные метрики

- Прибыло / обслужено / отказано
- Среднее и макс. время ожидания
- Макс. длина очереди
- Количество колонок (начало/конец)
- Доставки топлива, мин. остаток
- Загрузка каждой колонки (%)
- Статистика по дням

## Ответы на ключевые вопросы

### 1. Сколько колонок нужно для соблюдения порога ожидания?

**Условия:** 7 дней, порог ожидания 12 мин, seed=42

| Колонок | Скорость 20 л/мин | Скорость 5 л/мин |
|---------|-------------------|------------------|
| 1 | ср. 0.2 мин, макс. 3.4 мин | ср. 2.3 мин, макс. 43.1 мин → расширение до 3 |
| 2 | ср. 0.0 мин, макс. 0.9 мин | ср. 0.6 мин, макс. 9.4 мин |
| 3 | ср. 0.0 мин, макс. 0.0 мин | ср. 0.1 мин, макс. 4.0 мин |
| 4 | ср. 0.0 мин, макс. 0.0 мин | ср. 0.0 мин, макс. 1.7 мин |

**Вывод:**
- При стандартной скорости (20 л/мин): **1-2 колонки** достаточно
- При медленной скорости (5 л/мин): **2-3 колонки** для ср. ожидания < 1 мин
- Механизм авторасширения компенсирует недостаток колонок (1 → 3 за 7 дней)

### 2. Как часто пополнять топливо?

**Условия:** 7 дней, 2 колонки, начальный запас 10000 л, объём доставки 10000 л

| Интервал | Отказов | Мин. остаток |
|----------|---------|--------------|
| 12 ч | 0 | 8285 л |
| 24 ч | 0 | 6185 л |
| 48 ч | 0 | 2933 л |
| 72 ч | 89 | -25 л (дефицит) |

**Вывод:**
- **24 часа** — оптимальный интервал (запас > 6000 л, 0 отказов)
- **48 часов** — допустимо, но рискованно (запас падает до 3000 л)
- **72 часа** — недопустимо (возникает дефицит и отказы)

Формула безопасного интервала:
```
интервал ≤ (initialFuel + deliveryVolume) / среднийРасходВСутки
среднийРасход ≈ 200 авто × 17 л = 3400 л/сутки
интервал ≤ (10000 + 10000) / 3400 ≈ 5.9 суток (теоретический максимум)
```

### 3. Влияние неравномерной нагрузки

**Интенсивность по времени суток:**

| Период | λ (авто/мин) | Интервал | Относительная нагрузка |
|--------|--------------|----------|------------------------|
| Ночь (00-06) | 0.03 | ~33 мин | ×1 (база) |
| Утренний пик (06-10) | 0.25 | ~4 мин | ×8.3 |
| День (10-16) | 0.12 | ~8 мин | ×4 |
| Вечерний пик (16-20) | 0.30 | ~3.3 мин | ×10 |
| Вечер (20-24) | 0.08 | ~12.5 мин | ×2.7 |

**Влияние на систему:**

1. **Очереди формируются в пиковые часы (06-10, 16-20)**
   - Вечерний пик (λ=0.30) создаёт максимальную нагрузку
   - При 1 колонке и медленной заправке: очередь до 11 авто, ожидание до 43 мин

2. **Ночью система "отдыхает"**
   - Очереди рассасываются
   - Колонки простаивают (загрузка ночью < 5%)

3. **Потери клиентов (отказы)**
   - Возникают только при дефиците топлива, не от очередей
   - Пиковая нагрузка ускоряет расход топлива → риск дефицита к концу дня

**Рекомендации:**
- Планировать доставку топлива на утро (до пиков)
- При высокой нагрузке: минимум 2 колонки для сглаживания пиков
- Механизм расширения срабатывает с задержкой (2 дня) — не успевает реагировать на суточные колебания
